# Phase 4: Feature Engineering

## Overview

Feature engineering is the process of transforming raw transaction data into meaningful customer-level features that can be used by machine learning algorithms. The original dataset contains individual transaction records, whereas customer segmentation requires one row per customer.

In this phase, transaction-level information was aggregated to create numerical features that describe each customer's purchasing behaviour, spending habits, product preferences, and overall shopping patterns.

The final output of this phase is a customer-level dataset that serves as the input for customer segmentation.

---

# Objectives

The primary objectives of this phase were:

- Convert transaction-level data into customer-level data.
- Engineer meaningful behavioural features.
- Remove dependency on raw transactional records.
- Create features suitable for clustering algorithms.
- Validate the engineered dataset before saving.

---

# Input Dataset

Input File:

data/processed/final_cleaned_dataset.csv

The cleaned dataset contains one row per transaction with columns such as:

- CustomerID
- InvoiceNo
- InvoiceDate
- Quantity
- Revenue
- StockCode
- Country
- IsCancelled

Each row represents a purchased product within an invoice.

---

# Why Feature Engineering?

Machine learning algorithms cannot directly learn meaningful customer behaviour from raw invoices.

For example:

Customer A

Invoice 1 → ₹500

Invoice 2 → ₹1200

Invoice 3 → ₹800

Customer B

Invoice 1 → ₹2500

Invoice 2 → ₹3000

Although both customers have multiple transactions, Customer B clearly spends more money.

Feature engineering summarizes this information into meaningful numerical values that represent each customer's behaviour.

---

# Features Created

A total of seven feature groups were created.

## 1. RFM Features

RFM is one of the most widely used customer analysis techniques.

### Recency

Number of days since the customer's last completed purchase.

Business Meaning:

Lower Recency indicates recently active customers.

### Frequency

Number of completed invoices placed by the customer.

Business Meaning:

Higher Frequency usually indicates loyal customers.

### Monetary

Total revenue generated by the customer.

Business Meaning:

Measures overall customer value.

---

## 2. Purchase Features

These features describe purchasing quantity.

Features created:

- TotalQuantity
- AvgQuantity
- MedianQuantity
- MaxQuantity
- MinQuantity
- QuantitySTD

Purpose:

Understand how much customers purchase and how consistent their purchasing quantities are.

---

## 3. Spending Features

Revenue was first aggregated at the invoice level and then customer-level statistics were calculated.

Features:

- AvgRevenue
- MedianRevenue
- MaxRevenue
- MinRevenue
- RevenueSTD
- RevenueRange

Purpose:

Measure customer spending behaviour instead of purchase quantity.

Using invoice-level revenue avoids treating every product line as a separate purchase.

---

## 4. Product Features

These features describe product purchasing behaviour.

Features:

- UniqueProducts
- AvgProductsPerInvoice
- ProductDiversity

Purpose:

Identify whether customers repeatedly buy the same products or purchase a wide variety of items.

Product Diversity is calculated as:

ProductDiversity = UniqueProducts / Frequency

This represents the average number of unique products purchased per completed invoice.

---

## 5. Behaviour Features

These features describe purchasing habits over time.

Features:

- WeekendPurchaseRate
- ActiveMonths
- PurchaseSpan
- AvgDaysBetweenPurchases

Purpose:

Measure customer activity, shopping frequency, and purchase intervals.

---

## 6. Cancellation Features

Cancelled orders were analysed separately.

Features:

- CancelledTransactions
- CancelledRevenue
- CancellationRate

Purpose:

Identify customers who frequently cancel orders and measure their cancellation behaviour.

---

## 7. Country Feature

Each customer was assigned their most frequently occurring country.

Purpose:

This feature is mainly used for business analysis and cluster profiling.

Since it is categorical, it will not be used directly for K-Means clustering.

---

# Merging All Features

After creating individual feature tables, they were merged using CustomerID.

The final dataset contains one row per customer and combines all engineered features into a single table.

This customer-level dataset is much more suitable for machine learning than the original transaction-level data.

---

# Feature Validation

Before saving the dataset, several validation checks were performed.

- Checked missing values.
- Verified unique CustomerID records.
- Reviewed dataset information.
- Examined statistical summaries.
- Confirmed successful merging of all features.

These checks ensure that the dataset is complete and ready for modelling.
